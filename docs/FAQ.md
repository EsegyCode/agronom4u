# Maintainer FAQ (Agronom4u)

Purpose: practical answers for editing and operating the Agronom4u site.

## How do I run the site locally?

Run `npm install`, then `npm run dev`. Use `npm run build` and `npm run preview` to test the production output.

## Where do I edit shared text such as site name and navigation?

Edit `src/data/site.ts`. It contains `SITE`, `NAV_ITEMS` and `FOOTER_COLUMNS`.

## Where is crop content stored?

Crop data is in `src/data/fieldCrops.ts` and `src/data/gardenCrops.ts`. Field crops use the `FieldCrop` shape and topic content keyed by slug.

## How do I add a new field crop?

Add a new object to `FIELD_CROPS`, implement a subroute under `src/pages/crops/field/[crop]`, add OG assets and update `docs/CONTENT-GUIDE.md`. TODO (owner): route generation details beyond the existing soy/wheat/corn/sunflower set are not automated in the data.

## Where is FAQ content?

`src/data/faq.ts` exports `FAQ_ITEMS` with `question`, `answer` and `category` fields.

## How do I regenerate OG images?

Edit the `CARDS` array in `scripts/generate-og.mjs`, then run `npm run og` or `npm run build`.

## How is `/llms.txt` updated?

It is generated by `src/pages/llms.txt.ts` from crop, garden and blog modules. Rebuild to regenerate it.

## What should I check after a deploy?

Check the home page, crop pages, calculators, blog, FAQ, `llms.txt`, `robots.txt`, sitemap files and at least one `/og/*.png` URL. Run `npm run build` and `node scripts/verify-dist.mjs` first.

## Why does the build generate OG images twice?

`prebuild` runs `npm run og` and `build` also depends on it. `build:only` skips OG regeneration if assets are unchanged.

## Where are original agronomic notes?

`Аграрка.docx` in the project root. It is the source of norms, rotation and economics notes referenced in FAQ.
